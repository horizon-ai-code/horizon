# Multi-Agent Code Refactoring Benchmark Evaluation Report

## Overview & System Architecture

This report presents the empirical results of evaluating the multi-agent code refactoring framework against the monolithic single-model baseline. The data gathered from the benchmark execution provides detailed findings regarding algorithmic constraints, refactoring performance, and computational efficiency.

The researchers enhanced the code refactoring process by utilizing a multi-agent framework. Instead of a monolithic single-pass generation, the simulated agents are distributed into specialized roles—Planner, Generator, and Judge—operating with smaller 3B parameter models. This bounds the search and generation space, evaluates candidate outputs using deterministic compilation checks, and repairs errors iteratively. This makes the agents explore only high-quality partial solutions where the search space shrinks drastically, reducing wasted evaluations.

## 2. Refactoring Performance Evaluation

This section analyzes the compilation success rate, behavioral equivalence rate, cyclomatic complexity, and maintainability index between the Standard single-model approach and the Improved multi-agent framework.

> **Methodology Note (Funnel Methodology)**:  
> To maintain analytical consistency and avoid survivorship bias, the analysis in this section follows a strict funnel methodology. First, the Compilation Success Rate (CSR) is computed across the entire raw dataset ($n = 279$) to establish the absolute baseline of syntactically viable code generated by both paradigms. Second, the Logic and Quality Metrics (BER, CC, MI) are evaluated exclusively on Resolved Entries—the subset of code outputs that successfully compiled ($n = 189$ for Single-Model Baseline, $n = 163$ for Multi-Agent System). This ensures that non-compiling artifacts do not distort logical correctness or software complexity metrics.

## 3. Computational Efficiency and Hardware Resource Utilization

This section analyzes the comparison of inference time and peak GPU memory usage between the baseline and the proposed multi-agent framework.

![Inference Time Comparison](/home/pugario/.gemini/antigravity/brain/aa8842d0-a983-4614-8f62-9df9806e6a4b/images/duration_comparison.png)

**Figure 10. Mean Inference Time Comparison (Seconds per Task)**

![Duration Difference Wilcoxon Test](/home/pugario/.gemini/antigravity/brain/aa8842d0-a983-4614-8f62-9df9806e6a4b/images/wilcoxon_duration_diff.png)

**Figure 11. Wilcoxon Paired Difference Distribution for Execution Duration ($\Delta \text{Duration}$)**

In these figures, it presents the execution latency comparison. The single-model baseline had an average execution time of 19.47 seconds per refactoring task. The multi-agent system had an average execution time of 97.26 seconds per refactoring task, which is an approximate 5x latency increase due to the multi-agent iterative loop. For the statistical significance analysis focusing on normality and paired differences, statistical testing was conducted on paired execution metrics across all tasks (n=279 pairs) to capture the true operational overhead of the system. Using the Shapiro-Wilk Test for Normality on duration differences, the result was $W = 0.788$ with $p < 0.001$. In conclusion, the distribution of duration differences violates normality ($p < 0.05$). Consequently, parametric t-tests are invalid, requiring the non-parametric Wilcoxon Signed-Rank Test. Through the Wilcoxon Signed-Rank Test, the statistic was $W = 0.0$ with $p < 0.001$. This concludes that the overall execution time overhead of the multi-agent system is statistically significant ($p < 0.001$).

![Peak GPU Memory Comparison](/home/pugario/.gemini/antigravity/brain/aa8842d0-a983-4614-8f62-9df9806e6a4b/images/gpu_memory_comparison.png)

**Figure 12. Peak GPU VRAM Memory Allocation Comparison (MB)**

![GPU Memory Difference Wilcoxon Test](/home/pugario/.gemini/antigravity/brain/aa8842d0-a983-4614-8f62-9df9806e6a4b/images/wilcoxon_gpu_diff.png)

**Figure 13. Wilcoxon Paired Difference Distribution for GPU Memory ($\Delta \text{GPU Memory}$)**

In these figures, it presents the peak GPU memory allocation comparison and paired statistical analysis between the monolithic 7B baseline and the multi-agent 3B model pipeline. The single-model monolithic 7B baseline required an average peak GPU memory allocation of 4,044 MB VRAM. The multi-agent system utilizing 3B sub-models required an average peak GPU memory allocation of 3,232 MB VRAM, representing a 20.1% reduction in peak VRAM consumption, which saves approximately 812 MB.

For the statistical significance analysis regarding normality and paired differences, using the Shapiro-Wilk Test for Normality on GPU memory differences yielded a result of $W = 0.530$ with $p < 0.001$. In conclusion, the distribution of memory differences is non-normal ($p < 0.05$), confirming the requirement for non-parametric evaluation. Through the Wilcoxon Signed-Rank Test, the statistic was $W = 0.0$ with $p < 0.001$. This concludes that the overall reduction in peak VRAM usage achieved by the multi-agent framework is statistically significant ($p < 0.001$).
